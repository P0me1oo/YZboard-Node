# SS2022 连接关闭兼容补丁

源码来自 `SagerNet/sing-shadowsocks v0.2.8`，固定提交 `e0612494bafdd1429e9632bc52fd278585d28690`。原许可证和作者信息保留，原始文件校验值见 `UPSTREAM.json`。

Node 的混合内核中转测试发现：SS2022 首次应答在写入成功后设置 `serverConn.writer`，同时关闭连接的协程通过 `common.PtrOrNil(c.writer)` 读取它，两者缺少同步。上游 `v0.2.9` 的这段关闭逻辑相同，直接升级该版本不能解决问题。

`shadowaead.Reader` 和 `shadowaead.Writer` 没有独立的关闭操作，内部缓冲由 Go 管理；它们的 `Upstream()` 都指向已有的底层连接。原 `common.Close` 会沿这些包装重复关闭同一连接。本补丁仅将 `shadowaead_2022/service.go` 中的关闭方法改为关闭底层连接一次，既不访问正在初始化的写入器，也不改变协议格式、密钥、认证或转发数据。

补丁通过 Node 根模块的 `replace` 使用，随 Node 的固定提交一同发布，覆盖 Node 内嵌 Xray、sing-box 和测试客户端对这一原模块的调用。构建信息会同时显示上游来源和兼容目录；它不表示独立发布的上游 SS2022 库已修复。

新增测试并发执行首个普通应答或批量应答与连接关闭，同时验证底层关闭次数、错误传递和重复调用行为。CI 显式执行该依赖包的并发检测，并保留 Node 完整中转和用户生命周期测试。

后续上游提供等价修复、通过同一组测试且保持接口兼容时，可以删除本目录及根模块替换，固定到新的上游版本。
